# scripts/

Helper scripts for the capture → build → swap → test loop.

| Script | Stage | Purpose | Status |
|---|---|---|---|
| `01-capture-failure.sh` | diagnose | Launch Endfield via CrossOver with `CX_LOG` + `--wait-children`, collect logs + crash reports, auto-classify the failure (now recognizes the stage-1 protector loop). | ✅ working |
| `fetch-dwproton-patches.sh` | 2 | Pull the Endfield-relevant dw-proton patch set into `../patches/x64/stage2-dwproton/`. | ✅ working |
| `build-wine.sh` | build | Build a **64-bit-only** CrossOver 26.3 Wine from source (standard toolchain, no `win32on64`/`cx-llvm`). `deps\|fetch\|apply\|configure\|build\|all`. | ✅ working |
| `build-moltenvk.sh` | build | Build a patched x86_64 **MoltenVK** (`libMoltenVK.dylib`) from source into `build/moltenvk-out`. `fetch\|apply\|deps\|build\|all`. `MVK_ARCH=aarch64` builds the arm64 one for the ARM payload; `MVK_FLAVOR=finewine` builds the FineWine runtime's (arm64, plus `patches/moltenvk` for ray tracing) into `build/moltenvk-out-finewine` from source directories of its own. | ✅ working |
| `package.sh` | package | Bundle `build/wine-out` + `build/moltenvk-out` into `dist/endfield-wine-modules` (+ tarball/checksums) for `apply-modules.sh` and the Patcher app. | ✅ working |
| `apply-modules.sh` | install | Install the packaged Wine modules **and** MoltenVK into a copy of CrossOver (`CrossOver_Endfield_Patch.app`). | ✅ working |
| `swap-into-crossover.sh` | build | Build `CrossOver_Endfield_Patch.app` from `CrossOver.app`: swap in the 3 patched modules (+ optional GPTK4 D3DMetal; MoltenVK is downloaded unless `SKIP_MVK=1`), re-seal, verify. | ✅ working |
| `create-bottle.sh` | setup | Create the `Arknights Endfield` bottle (Windows 11 64-bit, D3DMetal + DLSS + MSync), or re-apply those settings with `UPDATE=1`. | ✅ working |
| `build-local.sh` | build | One-stop local build of `FineWine Patcher.app`: `build-local.sh [all\|x64\|arm]` builds the x64 Wine modules and MoltenVK, the arm64 MoltenVK and the ARM payload (or just one side), assembles the app and verifies it. Stages whose output is up to date are skipped; `ARM_MODE=stock` copies CrossOver ARM's own modules instead. | ✅ working |
| `build-all.sh` | build | Builds everything in order: `build-local.sh [all\|x64\|arm]` (both payloads and `FineWine Patcher.app`), then `finewine-app/scripts/build-app.sh` (`FineWine.app`). `SKIP_PATCHER=1` or `SKIP_FINEWINE=1` builds one half. | ✅ working |
| `build-finewine.sh` | build | One-stop build of FineWine only: the FineWine MoltenVK, the Wine runtime from a fresh source tree, FEX, DXMT, the runtime checks, the runtime archive, then `FineWine.app`. `build-finewine.sh [all\|runtime\|app]`; `SKIP_TESTS=1`, `SKIP_ARCHIVE=1`. Does not touch the patcher. | ⚠️ written, not yet run end to end |
| `build-finewine-runtime.sh` | build | Builds FineWine's own Wine runtime from upstream Wine 11.21 plus `patches/ARM` and `patches/runtime` into `build/finewine-runtime` (about 40 minutes from scratch). Its `package` step adds FEX and DXMT when their builds exist, and strips the runtime (856 MB against 1.7 GB), keeping the debug symbols beside it in `build/finewine-runtime-symbols` for local debugging only. `archive` makes the release `.tar.xz` (about 93 MB) from the stripped runtime alone and refuses if any file still carries debug information. Add the result in FineWine under Settings > Add Runtime. | ✅ boots on stock macOS; with the two scripts below it runs x64 programs and Direct3D 11 (see `docs/project-information/20-finewine-runtime-spike.md`) |
| `build-fex.sh` | build | Builds FEX, the x64 emulator, for Windows ARM64EC and installs it in the runtime as `xtajit64.dll`. Downloads the llvm-mingw compiler into `build/llvm-mingw` (checksum-pinned) on first use. | ✅ working |
| `build-dxmt.sh` | build | Builds DXMT (Direct3D 10 and 11 on Metal) as ARM64X, with its DLSS-to-MetalFX (`nvngx.dll`) and NVAPI modules, and installs it in the runtime. Applies `patches/dxmt`. Builds LLVM 15 from source once; needs an Xcode with the Metal toolchain. | ✅ working |
| `test-finewine-runtime.sh` | test | Smoke-tests a built runtime in throwaway prefixes: prefix creation, a console program, generated code, x18 repair, x64 programs under FEX, a Vulkan device and Direct3D 12 through MoltenVK (ARM64 and x64, with and without DXMT selected), Vulkan ray queries and ray tracing pipelines, DLSS for Direct3D 12 and Vulkan as MetalFX (super resolution and frame generation), the GPU ids each layer reports, Direct3D 11 through DXMT, the DLSS entry points, and MSync. It also checks that programs are told about the Apple GPU. Test programs are in `tests/runtime/`. Shows no windows. | ✅ working |
| `test-moltenvk-raytracing.sh` | test | Runs the two ray tracing tests natively against a MoltenVK build (default `build/moltenvk-out-finewine`): `tests/moltenvk/raytracing.c` (acceleration structures, ray queries, host builds, serialization) `tests/moltenvk/rtpipeline.c` (a ray tracing pipeline with all six shader stages) and `tests/moltenvk/metalfx.c` (MetalFX upscaling and frame generation, and the reported GPU ids). No Wine involved. Needs `glslangValidator`. `lib/compile-rt-shaders.sh` compiles the pipeline test's shaders into one header. | ✅ working |
| `bench-finewine-runtime.sh` | test | Measures where the time goes: builds `tests/runtime/bench.c` (CPU, memory, atomics, Windows system calls and synchronisation) natively, for Rosetta, and as ARM64 and x64 Windows programs, plus the Direct3D 11 and 12 draw-call benchmarks, and prints one table. `WINEMSYNC=0` measures without MSync. Results and what was done about them are in `docs/project-information/22-performance.md`. | ✅ working |
| `lib/make-game-loader.sh` | build | Makes `FineWine Game.app` beside Wine's loader: a copy of the loader in an app bundle whose Info.plist says it is a game, which macOS needs before it will turn Game Mode on. Run by `build-finewine-runtime.sh package`. | ✅ working |
| `lib/build-steam-helper.sh` | build | Builds `runtime-extras/steam-helper/steam.c`, FineWine's stand-in for the Steam client, into a runtime (`share/finewine/steam/steam.exe`, x64). HoYoverse's games are started through it. Needs llvm-mingw in `build/`; skipped without it. Run by `build-finewine-runtime.sh package`. | ✅ working |
| `launch-endfield.sh` | play | Launch `Endfield.exe` directly through the patched app (adds `-force-d3d11`); optional Wine logging via `DEBUG=`. Kept for reference: direct launches are not a supported way to use FineWine and can stop at a black window on recent game builds. | ⚠️ unsupported |
| `notproton-register.sh` | steam | Register the FineWine-patched CrossOver as a NotProton runner for Steam Play on macOS. See [../docs/notproton.md](../docs/notproton.md). | ✅ working |

## The loop
```
1. scripts/01-capture-failure.sh                      # baseline: capture the 0x6CD268 fault
2. scripts/build-wine.sh all                          # build vanilla 64-bit CrossOver Wine
3. scripts/swap-into-crossover.sh build/wine-build64  # -> build/CrossOver_patched.app (re-signed)
4. CX_APP=build/CrossOver_patched.app scripts/01-capture-failure.sh   # confirm parity vs stock
5. apply a stage-1 experiment (docs/12), rebuild, re-swap, re-capture, compare 0x6CD268 behavior
```

`build-wine.sh` / `swap-into-crossover.sh` are verified working on the reference setup (Apple M4 Pro, macOS 27.0, CrossOver 26.3.0 — the full story is [../docs/13-working-solution.md](../docs/13-working-solution.md)). On other macOS/CrossOver versions expect some iteration; the loop above is how to debug it. How to use these scripts as a user: [../docs/installation.md](../docs/installation.md).
